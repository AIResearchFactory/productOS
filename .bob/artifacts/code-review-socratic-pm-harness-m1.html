Commit 1 · 70c43862 · fix(providers): agy false-positive auth errors

Fixes a regression where model responses that legitimately mentioned words like "authentication", "login", or "API key" in content would be mis-classified as auth failures. The fix: resolve on exit 0 + content immediately; only inspect stderr/failure output for auth signals.

Praise Correct inversion of auth-error detection logic

The "happy-path first" restructure (if (code === 0 && finalContent) { resolve(); return; }) is exactly right. It eliminates the entire class of stdout-scan false-positives without any new complexity. The early return prevents the error block from even being reached on success.

Tests Excellent regression test coverage

Two new integration tests use real fake-CLI scripts (not mocks) to exercise the fixed path: one with auth-laden content that must succeed, one with empty output that must reject. The cross-platform win32 branch in the test harness is also well-handled.

Minor antigravity trigger string removed, new one added without comment
node-backend/lib/providers/google.mjs

The original check included 'antigravity' as an ineligible-tier signal. The replacement adds 'failed to authenticate antigravity' — a more precise string — but the change is silent. A one-line comment documenting the known agy CLI error text would make future maintenance safer.

Nitpick errorOutput uses || stdout.trim() but stdout was already resolved
node-backend/lib/providers/google.mjs, error branch

In the failure path, const errorOutput = stderr.trim() || stdout.trim() still reads stdout. At this point stdout is either empty (the only way we reach this branch is !finalContent or non-zero exit) or contains partial garbage. Using stdout here can surface confusing output in error messages. Consider restricting it to stderr.trim() and separately surfacing stdout only when stderr is empty and we need diagnostic detail.

A. Backend Critics — node-backend/lib/critics/

Critical Heuristic vague-term detection breaks on first match only (silent cap)
node-backend/lib/critics/devils-pm.mjs · runDevilsPMHeuristics, line ~54

The loop over vagueTerms has a break after the first match with a comment "Cap to avoid overwhelming." This means a document containing both "fast" and "scalable" only ever reports one finding. The intent is good, but silently dropping the rest is opaque. Options:

  • Keep the cap but return the worst-ranked match instead of the first one.
  • Or remove the break and let the caller/test set a max-findings ceiling so all individual issues are visible.

The existing test asserts findings.length > 0 — it passes, but it doesn't catch the silent suppression.

Security Path traversal guard in /api/artifacts/audit is incomplete
node-backend/server.mjs · POST /api/artifacts/audit, ~line 1280

The traversal guard only fires when artifactPath.includes('..') or path.isAbsolute(). Encoded traversals (%2e%2e) and symlink-based paths bypass the string check. More importantly the artifactPath variable is never actually used to read a file in this handler — it is passed only to runArtifactAudit as metadata. If it is never used for I/O, the guard is unnecessary noise; if it will be used for I/O in future, switch to the already-present resolveProjectPath utility which does a proper prefix check.

Major AIService.isSupportedProvider is called but likely does not exist
node-backend/lib/critics/index.mjs · runArtifactAudit, ~line 95

The orchestrator calls AIService.isSupportedProvider(activeProvider, settings). The AIService class in this codebase exposes createProvider but not a static isSupportedProvider. If this method is absent at runtime, the entire audit silently falls back to heuristics for all users with an active provider — no error is surfaced. Verify the method exists, or replace with a simpler guard: if (activeProvider) { try { aiProvider = await AIService.createProvider(...) } catch {...} }.

Minor Timer leak possible in runCriticWithTimeout if criticPromiseFn throws synchronously
node-backend/lib/critics/index.mjs · runCriticWithTimeout

If criticPromiseFn() throws before returning a promise, the Promise.race never sees it. The try/catch wrapping the await catches this, but timer is still live until GC collects the closure. Wrap the invocation: Promise.race([Promise.resolve().then(() => criticPromiseFn()), timeoutPromise]) to guarantee the timer is always cleared.

Praise parseFindingsJson is robust and safely shared

Input validation (typeof text !== 'string'), defensive fallback UUID generation, severity normalisation, and String coercion on all fields. The JSON regex also handles markdown-fenced LLM output correctly — the test proves it with a real fenced block.

Praise All critics use temperature: 0.1 for deterministic structured output

Low temperature is the correct choice for JSON-emitting prompts. Noted explicitly for reviewers — this is intentional and correct.

B. Silent Learner Memory Bridge — learning-store.mjs

Minor Duplicate-check for recordSocraticDecision is too loose
node-backend/lib/silent-learner/learning-store.mjs · recordSocraticDecision

The guard !existingContent.includes(answer) checks if the raw answer string appears anywhere in the file. A short answer like "Yes" or "Daily" would immediately match a previous unrelated line containing those words, silently dropping the new decision. Use a more targeted check — e.g. checking for the full decisionLine or a composite key of question + answer.

Nitpick LaTeX $\rightarrow$ in markdown decision lines may not render in all viewers
node-backend/lib/silent-learner/learning-store.mjs · decisionLine template

The written line uses $\\rightarrow$ in the context file. Standard markdown renderers (GitHub, VS Code) do not render LaTeX math. Replace with an arrow character: →.
